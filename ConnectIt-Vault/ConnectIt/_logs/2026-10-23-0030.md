## Request

Rework tile-powers Stage 3 to the revised plan: power values defined once per tag in a tile catalog, builder tiles,
a catalog preview that is never saved, and the swap at match start. The owner committed the first build and the plan
revision first.

## Overview

- **Catalog and settings:** `UConnectIt_TileCatalog` (tag -> tile class + power; a plain tile class) is found from the
  level config, else the project default (`UConnectIt_ProjectSettings`).
- **Builder tiles:** `AConnectIt_BuilderTile` is the tile designers place. Its tag lives in the tile settings
  (`FConnectItTileInitialData::TilePowerTag`), so it reaches the board like the other settings.
- **Board tiles:** carry only the tag, id and ready turn, all plain data.
- **Rules:** take every catalog power, plus the level-wide tags from the Level director.
- **The swap:** builder tiles become catalog classes when the board is seeded (server) or first arrives (client).
- **Layout tool:** Preview Tile Catalog / Clear Tile Catalog Preview, with transient actors and the editor's temporary
  hide, so nothing is saved. Load places builder tiles; capture skips previews.
- **Build and tests:** built; 55/55 tests pass (`ConnectIt.Board.TilePowerData` rewritten).
- **Throughput back to normal:** 392,028 nodes/s, against 366k-379k. A first run read 69,649 while Windows had the
  CPU capped at 30% of its maximum frequency; the re-run was made with it at 99%.
