## Overview

- **Stages 1-2 check:** nothing missed. Stage 1 unchanged; Stage 2's added item (tile actors follow the board) is the
  `ShiftTiles` already built.
- **Stage 3, first build** (the class-held design): built and 55/55 tests pass. **Throughput 303,709 nodes/s** against
  364,987 with only the per-tile instanced power removed -- a copy of the values on every board tile, ~17% slower
  search even with no powered tiles.
- **Redesign (owner):**
  - Power values are defined once per tag, a level being part of the tag, in a **tile catalog**: tag -> tile class +
    power. The catalog is chosen on the level config, with a project default.
  - Designers place **builder tiles** that name a tag.
  - An editor preview swaps in the catalog's classes as transient actors (never saved); the swap is real at match
    start.
  - The board tile carries only the tag, ready turn and tile id.
- **Revised:** the plan's Stage 3, with the first build recorded and what stays and goes; the tile-power-setup note (a
  new current section, the earlier decision marked partly superseded); the open question's Current thinking.
