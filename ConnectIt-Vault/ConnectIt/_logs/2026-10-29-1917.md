## Request

Adventure-hub plan, Stage 3: starting a node and coming back.

## Overview

- **Progress rules:**
  - `BuildOpenPermanentActions(Loadout, Table)`: everyone's actions (no shard price, e.g. Place Piece) as the level's
    loadout sets them, plus each shard-priced action the player has uses of, with **match uses = permanent uses**.
    Turn uses and cooldown come from its loadout entry, or default to 1 and 0;
  - `MakeInventory(Table, Items)`: the saved item tags back to classes.
- **`UConnectIt_AdventureSubsystem`:**
  - `StartNode` (only an Available level node) remembers the node and the hub map, then starts the match through the
    match setup subsystem;
  - `GetPlayingNode` answers only in the node's own level;
  - `SeedPlayerState` sets up open / closed actions, the inventory and the node's item budget;
  - `RecordPlayingNodeResult` records the result once per match;
  - `ReturnToHub` opens the hub again.
- **GameMode:**
  - human players are seeded through the Adventure subsystem when the level is a node being played, otherwise as
    before;
  - at match end it hands over won / lost (the GameState's winner against the human's slot) and the human's
    inventory.
- **Deviation:** the hub isn't opened automatically at match end; the results screen calls `ReturnToHub` (Stage 6
  UI). The result is already saved by then.
- Tests: new `ConnectIt.Adventure.OpenSetUp`, `.Inventory`. Editor build clean, **77/77**; Game target clean.
- Plan: Stage 4 lives in [adventure-hub-map-plan](../design/adventure-hub-map-plan.md); `current_stage` → 5 (the map
  validator).

## Owner checks (PIE, once there is a hub to start from)

- Starting a node from a Blueprint (`Start Node`) opens its level with its preset. An open node gives Place Piece plus
  the actions you have shard uses for, a closed node its own loadout. The saved items are in the inventory.
- Win → the node is complete with its rewards; lose → only the inventory changes. Then `Return To Hub`.
