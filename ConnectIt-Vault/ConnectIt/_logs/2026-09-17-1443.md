## Request

Owner wants to start keeping game design notes in the vault at `ConnectIt/design/` —
explicitly not sure how to structure it yet, so just start writing notes rather than
designing a schema first. Asked for: a short note per existing base action (Place Piece,
SWAP, Board Shift) explaining how it works and its gameplay ramifications/gotchas, plus a
general design note for a new "tiles with powers" feature idea (a tile activates an effect
once scored on enough, e.g. a poison tile that lowers diagonal neighbors' multipliers),
with the given poison example plus 4 more sketched.

## Overview

Created `ConnectIt/design/` (new, deliberately not `_`-prefixed — no `_schema/_design.md`
exists, matching the vault's own naming rule that the `_` prefix means schema-governed).
Wrote 4 notes grounded in the actual current code (re-verified action behavior from source,
not from memory, including `UConnectIt_LineScoringRule::ApplyScoringLine` — a real,
previously-undocumented-in-design-notes detail: completing a line clears every piece in it
except the completing one, and increments every tile's multiplier by 1.0, which is exactly
the mechanic the "tiles with powers" idea leans on as a free charge counter). Flagged real
open design questions and balance gaps for each action (Board Shift currently has no cost
or turn-limit at all; SWAP's ownership rule isn't client-visible) rather than just
restating what the code does. Added a one-line pointer to `design/` in `ConnectIt/CLAUDE.md`
so future sessions can find it; no schema authored, on purpose.
