## Request

Tile-catalog-effects plan, Stage 1: effects own their tag and values.

## Overview

- `FConnectItTilePowerEffect` gains `GetPowerTag()` and `PassesGate(Context)`. Push, Vacuum, Repel and Chained return
  their native `ConnectIt.TilePower.*` tags.
- `FConnectItTilePower`:
  - `Name` and `FireAtMultiplier` are removed;
  - `GetTag()` (the effect's tag), `IsSet()` and `PassesGate()` go through the effect;
  - `Effect` is `EditAnywhere` again (lost in d599c93, which left catalog entries unable to pick an effect).
- **Gate:** a reusable `FConnectItMultiplierGate` (`FireAtMultiplier`), as a `Gate` value on Push, Vacuum and Repel.
  The chain asks the power's `PassesGate` before the cooldown.
- **Floor / ceiling stay** on `FConnectItTilePower`: `ClampMultiplier` reads them for every tile type (scoring, Adjust
  Multiplier, tiles added), so they weren't unread as the plan guessed.
- The rules, the chain's Tile Power Triggered event and the catalog all use `GetTag()`. Catalog validation reports an
  effect whose tag isn't its entry's key; the catalog is still a map until Stage 2.
- Tests: every test effect derives from `FConnectItTilePowerEffect_TestBase`, which sets the tag it reports and has a
  gate. New checks: each shipped effect's tag, a power known by its effect's tag, Push's gate closed and open.
- Editor build clean, 69/69 tests.
