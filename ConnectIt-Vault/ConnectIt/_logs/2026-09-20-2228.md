## Request

Owner asked whether `PermanentActionState` / `NumberedActionState` were being set at all.

## Overview

- **Root cause found: the PlayerState action state was never seeded for human players on a server.**
  `InitialiseActionState` was only reachable through `UTurnBasedActionsComponent::InitialiseFromLoadout`
  when the controller has authority, but `AConnectIt_PlayerController::BeginPlay` returns early for
  non-local controllers, so a server (dedicated, or a remote client's controller on a listen server)
  never ran it. The last PIE log (server + 2 clients) shows `Built …`/`initialised …` from the client
  controllers and neither `seeded action state` nor `NOT seeded` — the answer to the open question
  from the Stage 2/3 close: the new path was **not** live. With the Stage 3 mandatory gate every board
  request would have been rejected ("has no action state").
- **Fix:** new `AConnectIt_GameMode::SeedActionStateForPlayer`, called from `PostLogin`, seeds the
  joining player's PlayerState from `LevelConfig->PlayerLoadout` on the server (skips if already seeded,
  so a reconnecting player keeps their state and a listen-server host isn't clobbered). Logs
  `seeded action state for … (server, PostLogin)` or an Error naming what's missing. The AI still seeds
  itself through its controller; the component's own seeding is unchanged.
- Builds clean; **not PIE-tested**.
