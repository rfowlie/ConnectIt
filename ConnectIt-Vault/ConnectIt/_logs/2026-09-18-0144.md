## Request

Implement the registry-mapping-refresh fix from
[2026-09-18 — Registry mapping refresh on GameEvent complete](../_decisions/2026-09-18-registry-mapping-refresh-on-game-event-complete.md)
(from the same-day check-in). Plan-mode design pass, twice revised after owner pushback
on the first cut, then implemented.

## Overview

Codebase investigation (two Explore passes + a Plan pass, cross-checked against actual
source) found the obvious fix wrong: the plugin's existing `UGridPieceRegistryBase::UpdateMappings()`
reads `GetActorLocation()`, but `GameEvent` tags fire synchronously — before any
Blueprint-driven visual lerp moves an actor — so a rebuild at that instant reads stale,
pre-move transforms. It was also broken outright: `UGridPieceRegistryBase::TileRegistry`
(which `UpdateMappings()` dereferences) is never assigned anywhere in the codebase.

Owner pushed back on the first plan revision with two further corrections: the
`TileRegistry` dependency is a coupling smell (grid geometry bundled into the tile
registry, forcing the piece registry to depend on a whole other registry just for math),
and three bespoke `UFUNCTION`+`BindOnTagComplete` pairs is unnecessary boilerplate when
the event subsystem already gets notified of every tag's completion internally. Both
verified against source and built:

- **New `UGridDefinition`** (`UnrealGridMechanics` plugin, `Registry/` folder) — grid
  geometry extracted verbatim off `UGridTileRegistryBase`. Both registry base classes now
  hold it as a public sibling reference instead of one depending on the other.
  `UGridPieceRegistryBase::TileRegistry` removed entirely; `UpdateMappings()` (both
  classes) fixed to use it instead of the null dereference (still not wired to fire
  automatically — same timing hazard applies regardless of which function does the
  rebuild).
- **New `UGameEventTaskSubsystem::OnAnyTagComplete`** — a generic "any tag just
  completed" delegate, one line added inside the existing `HandleOnManagerComplete`.
  Additive; doesn't touch `BindOnTagComplete`'s per-tag mechanism or either of its two
  existing callers.
- **The actual fix**: `UConnectIt_PieceRegistry` binds once to `OnAnyTagComplete`
  (`UConnectIt_BoardRegistrySubsystem::OnWorldBeginPlay`/`Deinitialize`) and dispatches
  internally by tag to re-key `PieceMap` directly from `FConnectItBoardChangeEvent`'s own
  authoritative before/after positions — never actor transforms. Only `PieceRegistry` —
  confirmed by reading the Mediator directly that shifts/swaps/captures never move or
  reassign a tile actor, only rotate/swap abstract per-position data.

Three new `_decisions/` notes record the non-obvious calls (extraction, generic delegate,
re-key-not-rebuild); two existing `code/` pages updated to match
(`UConnectIt_BoardRegistrySubsystem`, `UGameEventTaskSubsystem`) plus a new inventory row
for `UGridDefinition` in `UnrealGridMechanics/code/__INDEX.md`.

**Not yet verified** — no build/PIE run from this session; see Flags.
