## Request

Both registries need access to `UConnectIt_BoardStateComponent` (on GameState) when initialized by the subsystem — asked how to do this given the subsystem only knows the plugin's generic base types, and proposed creating ConnectIt-specific registry subclasses that the subsystem would hold instead.

## Overview

Investigated for existing precedent — found none; the one existing ConnectIt registry subclass (`UConnectIt_PieceRegistryComponent`) is dead, unwired scaffolding on the wrong base (the `ActorComponent` variant, not the `UObject` prototype variant this project actually uses) and was left alone. Designed and implemented `UConnectIt_TileRegistry`/`UConnectIt_PieceRegistry` (subclassing the plugin's `UGridTileRegistryBase`/`UGridPieceRegistryBase`), each adding a `GetBoardState()` that pulls `UConnectIt_BoardStateComponent` **on demand** via the existing `UConnectIt_GameUtilityLibrary::GetBoardStateComponent()` — the same resolution `UConnectIt_BoardRequestMediator` already used. No injection needed: since `UConnectIt_BoardRegistrySubsystem` already constructs each registry via `DuplicateObject(Template, this)`, outered into the world, `GetWorld()` already resolves correctly — the registries just needed to know to ask.

Retyped `ConnectIt_LevelConfigDataAsset`'s `TileRegistry`/`PieceRegistry` template properties to the new subclasses, narrowing the `Instanced` class-picker. Determined `UConnectIt_BoardRegistrySubsystem` itself needed **no functional change** — `DuplicateObject` preserves an object's dynamic class regardless of the template parameter's static type — though this was offered as optional cosmetic polish, which the user then did independently.

## Created

- `UConnectIt_TileRegistry`, `UConnectIt_PieceRegistry` (`Source/ConnectIt/Public/Board/`)

## Changed

- `ConnectIt_LevelConfigDataAsset` — `TileRegistry`/`PieceRegistry` template properties retyped from the plugin base classes to the new ConnectIt subclasses

## Flags & Follow-ups

- Noted `UConnectIt_PieceRegistryComponent` as dead/unused scaffolding on the wrong base class — flagged, not removed (out of scope for this request).
- Recommended, but didn't implement, retyping `UConnectIt_BoardRegistrySubsystem`'s own storage/accessors to the concrete subclasses for readability (not functionally required) — the user did this themselves shortly after (see `[[2026-09-09-5]]`, which debugs a regression introduced around the same time).
