## Request

Talk through where a modular Crumble mechanic should live, and whether the hardcoded board
requests in the mediator should become request objects mirroring the player actions. Then record
what was settled.

## Overview

Design discussion only — no code. Read the mediator, `BoardRules` and `BoardStateComponent`
first. Settled: board changes are layered (primitives / 1:1 request objects paired to actions /
one shared pipeline / an ordered `BoardReactions` array on `LevelConfig`); the `ChangeEvent`
becomes an ordered list of semantic steps with the step index carried through the game-event
queue; the Crumble threshold is stamped onto replicated board state like `TargetScore`. Also
found that `ProducesRequestType` is 1:1 in practice, PlacePiece authors its `RequestType`
differently from Swap/Shift, and five request types have no action.
