## Request

Root cause of the "PlacePiece hover doesn't light up on a duplicated map" bug turned out
to be a missing `ConnectIt_LevelConfigSettings` entry for the new level. User asked to
either document the level-creation step, or add a default-config fallback with a warning
— framed as three options, leaning toward the fallback.

## Overview

Chose the fallback over documentation: added `DefaultLevelConfig`
(`TSoftObjectPtr<UConnectIt_LevelConfigDataAsset>`) to `UConnectIt_LevelConfigSettings`,
and changed `UConnectIt_GameUtilityLibrary::GetLevelConfig` to fall back to it (logging a
`Warning` naming the level) instead of logging an `Error` and returning null when the
current level has no `LevelConfigs` entry. Reasoning and the documentation-vs-fallback
tradeoff written up as a `_decisions` note rather than `_discussions`, since this is a
settled call with a clear "why," not an open-ended Q&A.

## Flags & Follow-ups

- `DefaultLevelConfig` still needs to be set once in Project Settings (ConnectIt Level
  Config) for the fallback to actually do anything — until then a level with no
  `LevelConfigs` entry still hits the (now second) `Error`-and-null branch. Recommend
  pointing it at the existing sandbox `LevelConfigDataAsset`.
- Separate, not addressed here: the user flagged that the Actions UI is currently
  hardcoded to always show "Place Piece"/"Swap Piece" buttons rather than reading actual
  available actions from PlayerState/loadout — a rapid-prototyping shortcut now worth
  fixing since the underlying data (loadout, `SwapUsesRemaining`) is confirmed working.
  Not tracked as a task yet — flagging here in case it should be added to
  `ConnectIt/_tasks/active.md`.
