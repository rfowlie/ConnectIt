## Request

Use the Dataview plugin in the hand-built tables, add properties where they make the tables better, and add a `__PLUGINS` note in `_core` tracking the plugins the vault uses.

## Overview

- **Indexes now generated from note properties.** Decisions, logs, recipes, systems, design plans and design-to-decision links are Dataview queries. The hand tables couldn't stay current: the decisions table was missing 17 notes and the older rows used a different link format.
- **Properties added so the tables have something to show:**
  - decision notes: `summary` (84 notes; from the index row where there was one, otherwise the first sentence of the Decision section);
  - log notes: `summary` (154; from the index bullets, otherwise the first line of the Request section);
  - systems: `status` (current / retired) and `summary`;
  - recipes: `status`;
  - plans: `started`, `stages`, `current_stage`. The three hyphenated plan properties (`approved-on`, `completed-on`, `current-stage`) are renamed to underscores so Dataview can read them directly; 21 files changed.
- Templates (`TSchemaDecisions`, `TSchemaLogs`, `TCodeSystem`, `TCodeRecipe`) and the decision and log schema notes describe the new properties.
- **New `_core/__PLUGINS.md`:** the Dataview community plugin (0.5.68), the enabled and disabled core plugins, and the rule to update it when a plugin changes.
