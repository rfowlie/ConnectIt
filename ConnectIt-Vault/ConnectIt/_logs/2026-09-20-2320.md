## Request

Designer-placed tile values (e.g. a starting multiplier of 3) were being overwritten back to 1; the same
mechanism must also say whether a tile starts with a piece.

## Overview

- **Root cause:** `InitialiseBoardState` built every tile's data from defaults and never read the tile
  actors (`AGridTileBase` has no data properties).
- **Fix (owner chose the Blueprint-interface approach):** new `IConnectIt_TileDataProvider` +
  `FConnectItTileInitialData`; `InitialiseBoardState` reads each implementing tile (multiplier, active,
  shiftable, starting faction piece), validates the faction slot, and logs a summary. The initial snapshot
  is flagged `bBoardSeeded` and queues a new `ConnectIt_Event_BoardSeeded` tag (server + clients) so a
  Blueprint reaction can create visuals for starting pieces.
- **Written, NOT compiled** — the editor was open. Needs a build, then PIE.

## Flags & Follow-ups

- **Owner Blueprint steps:** add the interface to the tile Blueprint(s) and implement `Get Initial Tile Data`
  from the per-instance variables; add a reaction to `ConnectIt_Event_BoardSeeded` that spawns a piece per
  starting piece; set the values on the placed tiles.
- Until that reaction exists, starting pieces are in the board state but have no visual.
- A late-joining client won't get the seed event (it only sees the latest snapshot).
- A starting 3-in-a-row is not scored at start; it would only score if a later move completes a line.
