## Request

User noticed `Development/CLAUDE.md` links render differently from the wikilink-aliased
Domains table (`[text](path)` vs `[[target|display]]`), asked for the trade-offs, then
decided: the vault's structural churn is settling down, so switch to Markdown links as
the vault-wide standard for the reasons that favor an AI co-developer reading paths
directly. Four asks: (1) an atomic note on the trade-off, (2) record the decision in
`_core/CLAUDE.md`, (3) convert every `CLAUDE.md` to Markdown links, (4) a new `fix-links`
skill — a vault-health check for broken Markdown links that proposes fixes with the
user's confirmation rather than applying them blind.

## Overview

- **Two new `_core/_atomic/` notes** (the vault's first two real ones beyond its
  meta-explainer): `wikilink-aliases-separate-target-from-display.md` (the target/display
  split, both syntaxes) and `link-format-choice-depends-on-maintainer-and-consumer.md`
  (which mechanism to actually pick, and why the answer changed for this vault).
- **`_core/CLAUDE.md`** gained a new `## Link format` section recording the standard and
  its rationale, and its one remaining `[[TSchemaLogs]]` wikilink was converted.
- **All 9 `CLAUDE.md` files converted** from `[[wikilinks]]` to Markdown links: root,
  `ConnectIt`, and the 7 `Unreal*` plugins. Every converted link was checked to resolve
  against the current on-disk paths (post the `index.md`→`__INDEX.md` /
  `README.md`→`__README.md` rename the user had already run) — zero broken.
  `Development/CLAUDE.md` was left untouched — it was already Markdown-link style;
  its pre-existing broken links (found while explaining the trade-off last turn) are
  flagged in `ABOUT.md` for a future `fix-links` run, not fixed here.
- **`fix-links` skill created** (`_core/_skills/fix-links.md`), mirrored to
  `ConnectIt-Vault/.claude/skills/fix-links/SKILL.md` (the vault-scoped `.claude/`, not
  the repo-root one — matching where `process-*`/`ask-vault` are already mirrored).
  Cataloged in `_core/_skills/__INDEX.md`. Scoped to Markdown links only — `[[wikilinks]]`
  are explicitly out of scope since Obsidian keeps those correct on its own. Proposes
  fixes (same-basename-elsewhere, or the vault's own known rename patterns) but never
  applies one without the user confirming it.
- **`ABOUT.md`** — new Conventions bullet for the link-format standard; Changelog entry;
  two new Open questions (`Development/CLAUDE.md`'s dead links; the repo-root
  `.claude/skills/` set that doesn't match this vault's catalog, likely belonging to
  `Development/` instead).
- **Found and designed around a mirror-depth bug while building `fix-links`**: a
  `.claude/skills/<name>/SKILL.md` mirror sits one directory level deeper than its
  authored `_core/_skills/<name>.md` source (the extra `<name>/` wrapper folder), so a
  relative link correct in the authored copy reads as broken in every mirror —
  reproduced it against the existing `process-code` mirror to confirm it's systemic, not
  new. `fix-links` therefore excludes `.claude/skills/**/SKILL.md` from its scan by
  design (checking the authored copy is sufficient) rather than reporting a whole class
  of false positives. Also swapped `fix-links.md`'s own cross-references from clickable
  relative links to plain vault-root-relative code-span paths, so the file reads
  correctly regardless of which of its two locations it's opened from. In the same pass,
  fixed one genuinely pre-existing broken link noticed while editing
  `_core/_skills/__INDEX.md` (`_skills.md` → `../_schema/_skills.md`).
