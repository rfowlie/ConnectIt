## Overview

was added to the vault, by a different session, after that count). Converted all 9:

- The two `_core/_schema/` files (`_logs.md`, `__README.md`) — real relative Markdown
  links (`[TSchemaLogs](../_templates/TSchemaLogs.md)`), since schema files are never
  mirrored elsewhere, so a relative link is safe there.

  (`` `_core/_templates/TSchemaLogs.md` ``), not clickable links, per the mirror-depth
  lesson from the previous run: a `.claude/skills/<name>/SKILL.md` mirror sits one
  directory deeper than its authored source, so a relative link correct in the authored
  copy resolves wrong once mirrored.

All 7 skills re-mirrored to `.claude/skills/<name>/SKILL.md` afterward and confirmed
byte-identical. `fix-links.md`'s mirror was already in sync (no content change needed
there this run).

**Filename collision, caught and fixed.** First wrote this note to `2026-09-11-1500.md`
without reading what was already there — an unrelated, already-committed log entry (a
much larger `Development/optimal-co-developer/` + `_`-prefix-reversal session, commit
`9b50049`) occupied that exact timestamp and got overwritten. Recovered the original
content via `git show 9b50049:...` and restored it before refiling this note under the
`-2` collision suffix `_schema/_logs.md` itself prescribes. No content was permanently
lost, but this happened at all because a log file was written without reading current
disk state first, in a session that had just been told several other files changed
underneath it — the same caution should apply to log notes, not just the content files.
