## Request

Owner asked for two fixes flagged at the end of the last `/session-open` run: (1) clean up
the stale repo-root `.claude/skills/` mirrors, (2) make explicit that `ConnectIt/CLAUDE.md`

`_tasks/active.md`, `_meetings/`, and `_decisions/` live instead.

## Overview

**Repo-root skill mirrors:** `git rm`'d the entire repo-root `.claude/skills/` (tracked,
last touched by pre-`_core`-migration commits) — six stale/retired skills
(`ask-the-board`, `ask-vault`, `improve-system`, `reconcile-tasks`, `session-close`,
`session-open`), all diverged from their `ConnectIt-Vault:`-scoped counterparts (generic
`game-projects/`/`GameDeveloperVault/` paths that don't exist in this vault; `reconcile-tasks`
was retired vault-wide back on 2026-09-12 in favor of `process-tasks` and shouldn't have
existed anywhere). Left uncommitted — a git-tracked deletion, not committing without being
asked. With these gone, the vault's own `ConnectIt-Vault/.claude/skills/` mirrors resolve
by their plain names instead of needing the `ConnectIt-Vault:` prefix.

**`CLAUDE.md` shape:** Added an explicit, permanent guardrail section to
`ConnectIt/CLAUDE.md` — "Current state lives elsewhere, not here" — stating the file must
never carry a "Current state" or single-next-action section again, and naming exactly what
to read instead (`_tasks/active.md`, the newest `_sessions/` note, the newest
`optimal-co-developer/_meetings/` note, recent `_decisions/` notes). This closes a real
inconsistency: `session-close.md` (both game domains and Development-authored) still had a
step telling it to rewrite `Current status` back into the domain `CLAUDE.md` on every
close, which would have silently reintroduced the exact section the owner just removed.
Rewrote both `Development/_skills/session-open.md` and `session-close.md` so neither skill
expects or writes that section — `session-open` now sources "where we are" / "the one next
thing" / "not touching" from `_tasks/active.md` + `_meetings/` + `_decisions/` instead of
`CLAUDE.md` fields that no longer exist; `session-close` no longer touches `CLAUDE.md` at
all, only the session note's own `## Close` half (plus, where relevant, surfacing a task
candidate for the owner to add by hand). Re-mirrored both to
`ConnectIt-Vault/.claude/skills/`.
