## Request

User asked whether a skill exists to sweep `_data/` notes and generate atomic notes from
them (it doesn't); then asked to build it, with four requirements: `/process` must run
`process-data` before `process-atomic`; a `TSchemaWiki` template with an
atomic-sweep-tracking property; `/process-atomic` extended to sweep un-swept wiki notes
into `_core/_atomic/` (link+update existing topics, create new ones); atomic notes' word
cap raised 500 → 1000.

## Overview

Confirmed via an Explore agent that no such mechanism existed: `_schema/_atomic.md`
frames atomic-note creation as manual distillation, `process-data.md` stops at
`wiki/<slug>.md` synthesis, `process-atomic.md` only consolidated stray duplicate atomic
folders — neither read `_data/` content or wrote to `_core/_atomic/`. No `_data/` folder
exists anywhere in the vault yet, so this was new schema plumbing, not a backfill.

Built the requested capability:

- `process.md` now states the `process-data`-before-`process-atomic` ordering as a fixed
  dependency (it already ran in that order by list position; that was incidental before,
  now explicit and protected against future reordering).
- New `TSchemaWiki` template formalizes `_data/wiki/<slug>.md`'s frontmatter — `source:`,
  `updated:`, `atomic-summary: false` (kebab-case, per this vault's established
  multi-word-key convention — user said "atomic summary"; flagged the spelling choice in
  the approved plan), `tags: [wiki]`, plus a `## Atomic notes swept` section.
  `_schema/_data.md` and `_schema/__README.md` updated to reference it (`raw/` remains
  templateless).
- `process-atomic.md` restructured into two explicit passes: Pass 1 is the original
  duplicate-folder consolidation, unchanged. Pass 2 sweeps every `_data/wiki/*.md` not
  marked `atomic-summary: true` (or missing the field — swept anyway, flagged as
  predating the template), extracts atomic-note-worthy ideas per `_schema/_atomic.md`'s
  own "what becomes an atomic note" rule, links to / updates an existing
  `_core/_atomic/` note if the topic is already covered or creates a new one per
  `TSchemaAtomic` if not, then marks the wiki note swept. Never touches `_data/raw/`.
  Re-mirrored to `.claude/skills/process-atomic/SKILL.md`.
- Atomic-note word cap raised 500 → 1000 in `_schema/_atomic.md`,
  `_templates/TSchemaAtomic.md`, and `_atomic/how this vault writes atomic notes.md`
  (also softened the now-inaccurate "fits on screen without scrolling" claim in each).
- Re-mirrored `process.md` to `.claude/skills/process/SKILL.md` (touched, so re-synced
  per the vault's authored-copy/mirror-must-match rule).
