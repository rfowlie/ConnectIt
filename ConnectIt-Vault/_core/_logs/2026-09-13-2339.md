## Request

Create a `/meeting-open` / `/meeting-closed` skill pair for
`Development/optimal-co-developer/_skills/`: `/meeting-open` runs a structured check-in
about the core project (progress, roadblocks, morale, etc.), `/meeting-closed` saves the
transcript plus a summary (overview, key points, insights, decisions, tasks).

## Overview

Authored both skills as a paired open/close bookend around a deliberate check-in
conversation, distinct from the existing `session-open`/`session-close` coding-session
bookend. `/meeting-open` reads the active game domain's `CLAUDE.md`, its `_tasks/active.md`,
the last `_meetings/` note, and `career-coach.md`/`user.md`, then asks six question groups
(Progress, Roadblocks, Decisions, Morale & energy, Priorities & scope, Anything else) one
at a time, in the Producer voice from `identity.md`/`soul.md`. It writes nothing itself.
`/meeting-closed` reads the conversation back to where `/meeting-open` ran and files it as
a dated `optimal-co-developer/_meetings/` note per `_schema/_meetings.md`, extended with
`## Overview` / `## Key Points` / `## Insights` and a verbatim `## Transcript` (mirroring
`_discussions/`'s transcript rule). A settled non-obvious decision gets its own
`_decisions/` note per the base `_meetings` schema's own rule; tasks raised are listed as
candidates only — `_schema/_tasks.md` reserves entering/prioritising tasks to the owner by
hand, so the skill never writes to `_tasks/active.md` directly.
