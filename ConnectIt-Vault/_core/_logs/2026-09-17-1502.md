## Request

Owner asked whether `/session-close` currently analyzes a session for decisions,
questions, and discussions worth filing. It didn't. Asked to close that gap by extending
`/session-close` itself (over the alternative of extending `/improve-system`, or leaving
it manual).

## Overview

Confirmed the gap first, precisely, before fixing it: re-read `Development/_skills/session-close.md`
fresh (scoped to just the reckoning + task candidates, nothing about `_decisions/`/
`_questions/`/`_discussions/`) and `_core/_skills/improve-system.md` fresh (does have a
"route session output to the right home" step, but its table is scoped entirely to
`Development/board-of-advisors/` owner-facing knowledge — no row for a game domain's own
`_decisions/`/`_questions/`/`_discussions/` at all). So neither existing skill covered
this for a domain like `ConnectIt` — every decision/question/discussion note created this
session happened because the owner asked directly or it was flagged in the moment, not
from any systematic sweep.

Added a new "Route decisions, questions, and discussions" step to
`Development/_skills/session-close.md`, run every close on whichever domain the session's
work belongs to: (1) non-obvious settled decisions get a `_decisions/` note written
directly (same bar/shape `/meeting-closed` already uses for meetings), (2) genuinely open
unresolved threads get listed as candidates only — never auto-created, matching how
`_tasks/` candidates are already handled, since judging "is this really worth a persistent
note" is an easy call to get wrong in either direction, (3) a real extended Q&A/technical
exchange gets *offered* for filing via `/process-discussion`, not auto-filed, since
picking which exchanges matter is a judgment call. An explicit "none of the three fired"
is named as a valid, real finding, not a skipped step. Updated the skill's frontmatter
`description` to state the new capability plainly. Re-mirrored to
`.claude/skills/session-close/SKILL.md`.
