## Request

`TileRegistry`/`PieceRegistry` living on `AConnectIt_PlayerController` felt wrong ("both of these objects should only exist one time in the world") — asked whether they should live on a subsystem instead, sourced from the level-config data asset.

## Overview

Investigated the registry base classes' lifecycle (`UGridTileRegistryBase`/`UGridPieceRegistryBase`'s `InitialiseRegistry()` does its own `TActorIterator` world-scan internally, independent of what owns it) and `UWorldSubsystem` timing (`OnWorldBeginPlay` is Epic's documented "runs after every actor's `BeginPlay`" hook — new ground for this project, no existing subsystem here used it). Designed and implemented `UConnectIt_BoardRegistrySubsystem`: one canonical registry pair per world, `DuplicateObject()`-ing its own runtime instances from `Instanced` templates on `UConnectIt_LevelConfigDataAsset` at `OnWorldBeginPlay` — the DataAsset's template is never used live, since a `UDataAsset`'s `Instanced` subobjects are shared/loaded-once and would mis-resolve `GetWorld()`/corrupt state across simultaneous worlds (editor+PIE, multi-client PIE). Removed both registries from `AConnectIt_PlayerController` entirely and repointed every call site.

Per the user's explicit "full symmetric fix" choice (of three options offered), also closed a pre-existing plugin gap while touching the same code: `UGridPieceRegistryBase` had no `ShutdownRegistry()` at all (asymmetric vs. `UGridTileRegistryBase`, already flagged as a TODO in the plugin's own unused `ABoardManagerBase` prototype) — added it, and filled in `ABoardManagerBase::EndPlay`'s matching TODO.
