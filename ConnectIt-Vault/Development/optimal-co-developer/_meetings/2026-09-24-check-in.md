Answers on the two asks:

**The designer-tile-data decision (09-20)** — the problem: board state used to rebuild from hard
defaults every match start, so any starting value you set on a tile Blueprint instance (a starting
multiplier of 3, say) silently got reset to 1. Fix:
- Tile Blueprints implement `IConnectIt_TileDataProvider::GetInitialTileData()`, returning
  multiplier/active/shiftable/starting-piece. `InitialiseBoardState` asks every tile for this; one
  that doesn't implement it just gets the old defaults. A separate struct was needed because
  `FConnectItTileData`'s fields are `BlueprintReadOnly`, so Blueprint can't construct one directly.
- Starting pieces get spawned visually through a new one-shot `BoardSeeded` event, so a starting
  position on the board actually shows the pieces designers placed, through the same visual path as
  a normal PlacePiece.
- **Flagged, not resolved:** it's written but not compiled, and there's a known gap — a
  late-joining client wouldn't get the one-shot event and so wouldn't spawn starting-piece visuals.
  Worth knowing before you rely on it for playtesting with a friend joining mid-setup.
