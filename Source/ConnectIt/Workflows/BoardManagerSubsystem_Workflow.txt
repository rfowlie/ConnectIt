ConnectIt Board Manager Subsystem — Workflow
=============================================

WHAT THIS IS
------------
UConnectIt_BoardManagerSubsystem (Source/ConnectIt/Public|Private/Framework/Subsystem/
ConnectIt_BoardManagerSubsystem.h/.cpp) is a per-world UWorldSubsystem that:

  1. Caches the single AConnectIt_BoardManager actor in the level, so lookups don't
     need to repeatedly scan the world for it.
  2. Relays OnShiftApplied -- the one board event still fired as a direct delegate
     (its tag-based equivalent is deferred, see ConnectIt_BoardManager.h) -- so
     listeners never need to know whether the board manager reference is valid yet
     before binding to it.

It always exists for the lifetime of the world (subsystems are created at world
init), which is the whole point: it is always safe to bind to or query, even before
AConnectIt_BoardManager itself has spawned or run BeginPlay.

NOTE: piece placed / line scored / player win are NOT relayed here any more -- those
are UGameEventTaskSubsystem tags now (ConnectIt_Event_PiecePlaced/LineScored/
PlayerWin). See Workflows/GameEventSubsystem_Workflow.txt. This subsystem used to
relay all four board events as typed delegates; that produced two parallel
notification systems for the same events (a typed delegate here and a tag on the
event subsystem) that had to be kept in hand-written lockstep -- consolidated down
to one channel per event. OnShiftApplied is the sole remaining exception because its
tag equivalent isn't built yet.


WHY IT EXISTS
-------------
UConnectIt_GameUtilityLibrary::GetBoardManager() used to do a full
TActorIterator<AConnectIt_BoardManager> world scan on every call. That function is
BlueprintPure and called from many client-side Blueprint call sites, some of them
multiple times per frame -- so the scan cost was being paid repeatedly for a value
that never changes during a match (one board manager per world).

NOTE ON ARCHITECTURE: this cache intentionally lives in a NEW subsystem in the
ConnectIt game module, not in the existing UGridWorldSubsystem (UnrealGridMechanics
plugin). AConnectIt_BoardManager is a ConnectIt-module class; ConnectIt already
depends on UnrealGridMechanics, so caching a strongly-typed AConnectIt_BoardManager*
inside the plugin would require the plugin to depend back on ConnectIt -- a circular
module dependency UBT rejects. Keeping the cache in ConnectIt's own subsystem avoids
that entirely.


HOW REGISTRATION HAPPENS (you should not normally need to touch this)
-----------------------------------------------------------------------
AConnectIt_BoardManager::BeginPlay() registers itself with the subsystem:

    if (UConnectIt_BoardManagerSubsystem* BoardManagerSubsystem =
        GetWorld()->GetSubsystem<UConnectIt_BoardManagerSubsystem>())
    {
        BoardManagerSubsystem->RegisterBoardManager(this);
    }

This call is OUTSIDE the HasAuthority() branch in BeginPlay, so it runs on both the
server and every client's local replicated copy of the actor. This matters because
most GetBoardManager call sites are client-side -- if registration only happened on
the server, clients would never populate their local cache.

RegisterBoardManager() is safe to call more than once (e.g. PIE re-entry): it
unbinds the event relay from any previously-cached board manager, then rebinds to
the new one. Last caller wins.


TWO THINGS CONSUMERS WANT, AND WHICH ONE YOU NEED
----------------------------------------------------
There are two distinct reasons code wants to reach the board manager. Picking the
right one matters -- using the wrong one is exactly the "backwards" pattern this
subsystem was built to get away from.

  (A) "I need to CALL something on the board manager"
      e.g. GetPlayerLoadout(), GetEnemyLoadout(), ProcessRequest(), InitialiseBoard()

      You need the actual object reference. Use one of:

        - UConnectIt_GameUtilityLibrary::GetBoardManager(WorldContextObject)
          The general-purpose entry point. Checks the subsystem cache and returns
          it directly. Does NOT fall back to a world scan any more -- if the cache
          is empty (subsystem missing, or board manager hasn't registered yet in
          this world), it logs a LogTemp Error and returns nullptr. A miss here is
          treated as a hard failure to surface immediately, not a race condition to
          silently paper over.

        - UConnectIt_BoardManagerSubsystem::GetBoardManager() [BlueprintPure]
          Same cached value, callable directly on the subsystem from Blueprint.
          Unlike the utility library version, this is a silent/pure accessor -- it
          returns null with no logging if the board manager isn't registered yet.
          Use this when you want to opportunistically check "do we have it yet"
          without treating a miss as an error (see the OnBoardManagerReady pattern
          below).

        - UConnectIt_BoardManagerSubsystem::OnBoardManagerReady (delegate)
          BlueprintAssignable, fires once with the AConnectIt_BoardManager* when
          RegisterBoardManager() runs. Bind to this from anywhere (Construct,
          BeginPlay, etc.) instead of polling GetBoardManager from Tick.

      Recommended Blueprint pattern for (A) when you can't guarantee the board
      manager already exists at the point you need it (e.g. a widget's Construct):

          Get Board Manager (subsystem) --> Is Valid? --> [true] use it directly
                                                       --> [false] Bind Event to
                                                            OnBoardManagerReady,
                                                            use the reference it
                                                            passes when it fires

  (B) "I want to REACT to something that happens on the board"
      e.g. a piece was placed, a line was scored, someone won, a shift was applied

      For piece placed / line scored / player win: you do NOT need the board
      manager reference at all, and you do NOT bind here. Bind to the matching tag
      on UGameEventTaskSubsystem instead -- see Workflows/GameEventSubsystem_Workflow.txt
      for the full pattern (BindOnTagBegin for "tell me now", a registered
      UGameEventTask_Async for "wait for my visual to finish"; read payload data via
      UConnectIt_BoardStateComponent::GetChangeEvent()).

      For shift applied specifically (deferred tag migration): bind to this
      subsystem's OnShiftApplied, which exists and can be bound at any time,
      regardless of whether the board manager has spawned yet:

        UConnectIt_BoardManagerSubsystem::OnShiftApplied  (const FShiftOperation&, const FShiftResult&)

      This mirrors AConnectIt_BoardManager's own OnShiftApplied. The subsystem binds
      itself to the real board manager's delegate once, inside RegisterBoardManager,
      and relays every broadcast through. Do NOT bind directly to
      Board->OnShiftApplied -- that reintroduces the exact "must prove the board
      manager exists before I can bind" problem this subsystem exists to remove.

      Example of what NOT to do:

          AConnectIt_BoardManager* Board = GetBoardActor();
          if (!IsValid(Board)) { log error; return; }   // binding depends on this
          Board->OnShiftApplied.AddDynamic(this, &AMyClass::HandleShift);

      What to do instead:

          if (UConnectIt_BoardManagerSubsystem* Subsystem =
              GetWorld()->GetSubsystem<UConnectIt_BoardManagerSubsystem>())
          {
              Subsystem->OnShiftApplied.AddDynamic(this, &AMyClass::HandleShift);
          }

      This binding no longer depends on the board manager already being resolved.


QUICK REFERENCE
----------------
  Need to CALL something on the board manager right now, and you're confident
  it already exists (e.g. server-side code after match start)?
      -> UConnectIt_GameUtilityLibrary::GetBoardManager(this)

  Need to CALL something on the board manager but can't guarantee timing
  (e.g. client-side widget)?
      -> UConnectIt_BoardManagerSubsystem::GetBoardManager(), fall back to
         binding OnBoardManagerReady if null

  Need to REACT to piece placed / line scored / player win?
      -> Bind to the matching tag on UGameEventTaskSubsystem. See
         Workflows/GameEventSubsystem_Workflow.txt. AConnectIt_GameMode::
         InitialiseBoard() (Source/ConnectIt/Private/Framework/GameMode/
         ConnectIt_GameMode.cpp) is the real example.

  Need to REACT to a shift being applied?
      -> Bind to UConnectIt_BoardManagerSubsystem::OnShiftApplied (deferred
         tag migration -- still a direct delegate for now).
